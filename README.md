# Knowledge Radar

**通过飞书收集、总结和讨论文章的自托管 AI 知识收件箱。**

把手机上发现的好文章发送给机器人，获取摘要与要点，继续追问，并将结果保存到自己的 Markdown 知识库。

[快速开始](#快速开始) · [使用示例](#使用示例) · [文档](#文档) · [参与贡献](#参与贡献)

## 为什么做这个项目

收藏链接很容易，真正读完、理解并整理成自己的知识却不容易。

Knowledge Radar 希望把“看到一篇好文章”到“留下可回顾的笔记”连起来：用飞书作为随手收集的入口，用 AI 辅助理解，用普通 Markdown 保存成果。先服务于个人日常使用，再逐步扩展为关注技术动态的信息雷达。

## 核心功能

- **随手收集** — 在飞书私聊中发送公开文章链接，无需额外安装手机应用。
- **文章摘要** — 自动提取正文，生成摘要和核心要点。
- **围绕文章讨论** — 根据最近的文章摘要继续追问，采集期间也能正常聊天。
- **Markdown 归档** — 以可读标题命名文件，保存来源与时间，接入已有知识库。
- **自托管部署** — 单个 Docker 应用容器，SQLite 保存运行状态，无需独立数据库服务。

> 当前为早期版本，支持单用户飞书私聊和公开文章采集。订阅、登录态浏览和可视化页面仍在计划中。

## 使用示例

在飞书中单独发送一个 URL，或使用：

```text
总结 https://www.cnblogs.com/uniqueDong/p/22889846
```

机器人先确认接收，完成后返回**文章标题、摘要、要点和归档文件名**。随后可以继续问：

```text
这篇文章最值得我关注的观点是什么？
```

摘要会保存为 `文章标题--短任务标识.md`，文档包含原文链接、时间、摘要和要点。普通聊天中提到链接不会自动打开网页。

## 快速开始

需要 Docker Compose、飞书自建应用和模型 API key。当前通过源码构建镜像，已验证 Windows Docker Desktop；宿主机无需安装 Node.js。

**1. 获取源码并准备配置**

克隆或下载仓库，在项目根目录执行以下 PowerShell 命令。已有 `.env` 时直接编辑，不要覆盖：

```powershell
Copy-Item .env.example .env
```

**2. 填写配置**

按照[飞书接入指引](docs/feishu.md#1-应用与配置)配置机器人，在 `.env` 中填写飞书凭据、模型与 API key，并设置 `KNOWLEDGE_RADAR_ARCHIVE_DIR_HOST` 为已创建的专用归档目录。

飞书使用长连接接收消息，无需公网域名或 Webhook 回调地址。完整配置示例见[使用指南](docs/usage.md#2-配置本地环境)。

**3. 启动服务**

```powershell
docker compose -p knowledge-radar-feishu -f compose.feishu.yaml -f compose.feishu.capture.yaml up -d --build
```

启动后即可向机器人发送文章链接。[查看日志、停止服务与故障排查 →](docs/feishu.md#3-状态与故障排查)

## 使用须知

- 当前只采集公开网页，不自动登录或绕过验证码、付费墙。
- 追问基于最近的摘要，不等于全文检索或永久记忆；重要信息请核对原文。
- 归档保存在本地，但聊天文字和文章正文会发送给配置的模型供应商，API 调用可能产生费用。
- 数据库与 Markdown 需要分别备份；升级前请阅读[使用与维护指南](docs/usage.md#日常使用与数据)。
