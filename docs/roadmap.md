# 迭代路线

路线图按可验证闭环排序，不按功能看起来是否完整排序。每个阶段完成后都应该能够单独演示和写一篇开发记录。

## Phase 0：设计文档

目标：明确系统边界，避免在框架、模型和浏览器自动化之间反复试错。

- [x] 项目定位和第一版边界
- [x] 系统架构
- [x] 技术选型
- [x] Agent 权限边界
- [x] 登录态方案
- [x] Docker 部署边界和持久化方案
- [x] 仓库目录和模块依赖规则
- [x] 关键架构决策记录

完成标准：文档能够回答第一版做什么、怎样运行、数据放在哪里、失败后怎样恢复。

## Phase 1：公开网页收件闭环

目标：从飞书发送一篇公开网页，最终得到一份可读的 Markdown 归档。

- 飞书长连接和用户白名单
- Docker 镜像和 Compose 部署入口
- 非 root、只读根文件系统、最小挂载和资源限制
- 健康检查、优雅退出和自动重启
- 消息幂等与 SQLite 任务表
- URL 安全检查
- 公开网页正文提取
- pi 摘要
- Markdown 归档
- 飞书结果回复

完成标准：连续处理多篇公开文章，进程重启后不丢任务、不重复归档。

## Phase 2：围绕文章对话

目标：用户可以在飞书继续追问，问答和文章保持明确关联。

- 飞书回复关系到文章会话的映射
- Agent 上下文投影与可恢复 Turn
- 对话追加归档
- 会话过期和重新打开
- 长回复分片或流式卡片

完成标准：重启服务后仍能继续最近的文章对话，并在 Markdown 中看到完整记录。

## Phase 3：博客技术雷达

目标：每天收到一条有优先级、低噪音的技术更新摘要。

- RSS / Atom 配置和解析
- 首次基线与新增文章去重
- 兴趣主题和来源优先级
- 候选文章批量筛选
- 每日定时摘要
- 通知 Outbox 和失败重试

完成标准：连续运行一周，没有历史文章轰炸、重复提醒或空摘要。

## Phase 4：登录态内容

目标：在不向 Agent 暴露密码和 Cookie 的前提下读取已授权页面。

- 独立 Browser Profile 管理
- 隔离的 Playwright 浏览器容器
- 默认仅绑定本机的人工登录界面
- 可选的手机免安装远程登录 overlay、Access 身份校验和一次性任务令牌
- 可见浏览器手动登录命令
- 登录页和内容不完整检测
- `waiting_auth` 状态
- 飞书重新登录提醒和任务重试
- 一个 Profile 串行访问

完成标准：登录一次后可多次读取授权页面；登录过期时不会误总结登录页，也不会丢失原任务。

## Phase 5：更多内容类型

根据真实使用频率决定顺序，不提前承诺全部实现：

- PDF 文本提取
- 飞书文件附件
- 图片 OCR
- Newsletter 邮件入口
- GitHub Releases 和 arXiv 查询
- 用户反馈驱动的摘要排序

## 暂不规划

- 自动注册和轮换网站账号
- 绕过验证码、付费墙或访问控制
- 多用户 SaaS
- 通用浏览器操作 Agent
- 自动博客发布
- 向量数据库
- 独立 Web 管理后台

这些功能只有在现有工作流出现明确瓶颈时才重新评估。
