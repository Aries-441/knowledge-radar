# ADR-0003：登录态优先于自动填写密码

- 状态：Proposed
- 日期：2026-09-04

## 背景

部分博客和社区页面需要登录才能获取完整正文。登录流程可能涉及密码、扫码、TOTP、短信、设备确认和验证码。让模型每次完成登录既不可靠，也会增加凭据泄露和账号风控风险。

Playwright MCP、OpenClaw、Browser Use、Skyvern 和 Browserbase 的共同做法，是保存浏览器状态并复用已经建立的登录会话。密码保险库和自动 TOTP 属于更进一步的能力，不是基础前提。

## 决定

采用 Session-first 认证：

1. 优先使用官方 API、私有 Feed 或匿名页面。
2. 需要登录时，为对应站点使用独立的低权限阅读账号和 Browser Profile。
3. 首次登录、扫码、验证码和异常验证由用户在可见浏览器中完成。
4. 后续任务复用 Profile 中的 Cookie 和浏览器状态。
5. 登录过期时进入 `waiting_auth`，通过飞书提醒并保留任务。
6. 第一版不保存网站密码，不自动生成 TOTP。

不使用日常浏览器主 Profile，不建立自动注册或轮换账号池。

## 结果

好处：

- 密码和验证码不经过模型。
- 更接近正常用户的稳定登录环境。
- 能处理扫码、SSO 和设备验证。
- 实现和维护成本低于完整凭据系统。

代价：

- 登录过期时需要人在电脑旁操作。
- Profile 是高价值敏感数据，需要隔离和备份策略。
- 某些平台仍会检测自动化或限制内容访问。

## 后续演进

如果低权限阅读账号频繁退出，可以增加 Vaultwarden/1Password 适配器：模型只看到占位符，执行器在受限域名内临时注入真实值。个人主账号、付费账号和高价值账号继续保留人工验证。

## 重新评估条件

- 需要管理多个真实用户的账号连接。
- 某个平台提供稳定 OAuth 或官方内容 API。
- 手动重新登录成为可量化的主要维护成本。
