# ADR-0001：通过适配器使用 pi SDK

- 状态：Accepted
- 日期：2026-09-04

## 背景

项目需要文章总结、内容排序和连续对话。pi 已经提供模型接入、会话管理、上下文压缩和嵌入式 SDK，但它的默认定位是编码 Agent，能力范围大于本项目需要的范围。

直接 fork pi 可以自由修改内部行为，但会长期承担上游升级、冲突解决和安全修复成本。直接绑定 pi 类型又会让应用层难以测试和替换。

## 决定

不 fork pi。定义项目自己的 `AgentRuntime` 接口，并提供一个 pi SDK 适配器作为默认实现。

第一版仅使用文本生成和受控的上下文重建，不启用 pi 的 Shell、浏览器、编辑和文件写入工具。会话恢复事实由 Radar SQLite 保存的安全上下文投影承担；不采用 `AgentHarness` 的 SQLite Session Backend，因为它不能与 Radar 的 Turn、Job、Outbox 事务原子组合。验证记录见[会话运行时与可恢复状态机](../conversation-runtime.md)。

## 结果

好处：

- 可以跟随 pi 上游升级。
- 核心业务可以使用假的 AgentRuntime 做测试。
- 将来可以增加直接模型 API 或本地模型实现。
- 限制 Agent 权限更容易审计。

代价：

- 需要维护一层薄适配器。
- pi SDK 发生破坏性变化时仍需更新适配器。
- 少量简单总结也需要加载相对完整的 pi 运行时。

## 重新评估条件

- pi SDK 无法稳定支持长期服务进程。
- SDK 依赖体积或启动成本明显影响常驻运行。
- 项目不再需要连续会话，只保留一次性摘要。
